🤖 What Is the AI Layer? Thinks & Plans

The AI layer is the "brain" that understands your questions and decides what to do. It runs on AWS Bedrock (primarily Claude Sonnet) and streams answers live. It never touches the database directly — it tells the Agent what tools to run.

💡 Think of it like a senior analyst

They read your question, check their notes (memory), look up the data dictionary (semantic layer), decide which query to write, and explain the results — but they don't run the query themselves. That's the Agent's job.

⚙️ What Is the Agent Runtime? Executes Safely

The Agent is the "hands" — it takes the AI's decisions and actually runs them. Every SQL query, chart, and schema lookup goes through the Agent. It enforces safety rules, records a full trace, and scores run quality.

💡 Think of it like a database gateway with a black box recorder

The Agent is the only thing allowed to touch Databricks. It checks every query is read-only, logs everything that happened, and reports back whether the run succeeded — so the system can learn from it.

🛡️ SQL Safety Gate (The Chokepoint)

Every single SQL query passes through executeDatabricksSQL() in databricks/execute.ts. No bypass exists.

1
Strip comments & string literalsPrevents smuggling dangerous SQL inside strings
2
Check first verb is read-onlyOnly SELECT, WITH, SHOW, DESCRIBE, EXPLAIN allowed
3
Block multi-statementSemicolons outside strings = rejected
4
Apply row & byte capsMax 1000 rows (configurable), 4MB response limit
5
Execute on DatabricksOAuth token → SQL Statements API → parse results
✗
Reject external_linksIf result too large for inline delivery → fail with "add LIMIT"

🧠 What Is the Memory System? Learns Over Time

Memory stores short, actionable rules learned from past sessions — like sticky notes that the AI reads before answering your next question. No model retraining needed; rules are injected into the prompt instantly.

💡 Think of it like a team wiki that writes itself

After every workday, the system reviews what happened in each chat session, extracts useful lessons ("crew data is in ops.crew_manifest"), and adds them to a shared knowledge base. Next time anyone asks about crew data, those lessons are automatically included in the AI's context.

📋 Five Types of Memory Rules

TypeWhat It StoresExample
HARD_RULEMust-follow safety rules"Never fabricate column names"
SCHEMA_MAPTable & schema paths"Crew data → ops.crew_manifest"
HEURISTICGeneral tips & patterns"Filter by voyage_id before joining"
SOURCE_PREFWhich data source to use"Vessel data is in curated_db"
FAILURE_MODEKnown error patterns"Unqualified name → TABLE_NOT_FOUND"

🔍 Three-Phase Retrieval — How Rules Are Found

When you ask a question, memory runs three searches in parallel. Click each phase:

0

INIT — Guardrails

Safety rules, always on

1a

SCHEMA — Facts

Table paths for this topic

1b

TASK — Recall

Semantic search by question

Phase 0 (INIT) — Injected into system prompt. Always includes a default guardrail ("verify tables exist"). Plus any HARD_RULEs with high confidence. No embedding search — deterministic. Budget: ~200 tokens.
Phase 1a (SCHEMA_GLOBAL) — All SCHEMA_MAP bullets for the current topic group. Sorted by confidence × net-helpful score. Plus your personal taught rules (recency-ordered). Injected into system prompt. Budget: ~600 tokens.
Phase 1b (TASK_SCOPED) — Your question is embedded (Titan), then cosine-searched against HEURISTIC / SOURCE_PREF / FAILURE_MODE bullets. Optional MMR diversity prevents redundant rules. Injected as a synthetic "assistant recall" message. Budget: ~1200 tokens.

🎓 Teach Mode & Reputation

Teach Mode

Correct the AI directly

Your correction → teach candidate → admin review → promoted to memory. Personal rules get a dedicated retrieval lane so they always surface for you.

Attribution Loop

Did the rule actually help?

Success → helpful_count++, confidence +0.02. Failure → harmful_count++. 3+ harmful → rule SUPERSEDED. Idempotent — safe to replay.

Reputation

Leaderboard for contributors

Season-based scoring. Users earn reputation when their rules lead to successful runs. Flag: MEMORY_REPUTATION_ENABLED

FOER Clustering

Organize rules by topic

Groups bullets by task_signature into topics like "crew-certificates" or "vessel-voyage". Enables Phase 1a to scope retrieval to the right domain.
