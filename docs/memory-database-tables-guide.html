DATABASE DATA DICTIONARY

Self-Improving Memory Database Tables

The 12 database tables that support ALOFT D360’s self-improving memory system: session traces, memory bullets, vector retrieval, attribution, synthesis, topics, Teach Mode, and job operations.

1. Scope and table count

12memory-subsystem tables
1vector-enabled table
11regular relational tables
0separate vector DB services
Scope note: This count covers the self-improving memory subsystem only. The Prisma schema also contains unrelated context, semantic, estate, analytics, and agent tables.

All 12 tables are stored in PostgreSQL. platform_agent_memory is vector-enabled because it has an embedding vector column. The other tables are relational support, audit, trace, or operational tables.

7. Vector search: exactly where it happens

Only platform_agent_memory.embedding participates in vector similarity search.

Question:
  "How many active crew certificates expire this month?"

1. embedQuery(question)
   → [0.11, -0.28, 0.74, ...]

2. PostgreSQL / pgvector:
   ORDER BY embedding <=> question_vector

3. Retrieve nearest ACTIVE rules:
   "expiry_date is a DATE column"
   "Filter status = 'ACTIVE'"

4. Write usage record:
   platform_memory_injections(bullet_id, run_id, phase)

5. Attribute the result:
   platform_agent_memory.helpful_count += 1
Important: The injection table does not contain embeddings. It only stores IDs and run metadata. The actual vector data is in platform_agent_memory.

8. Complete sample data flow

  1. Trace: platform_trace_nodes records a successful describe_schema result showing ops.crew_certificates.expiry_date.
  2. Synthesis: reflectSession proposes a rule; curate validates and embeds it.
  3. Memory: The rule is inserted into platform_agent_memory with an ACTIVE status and vector.
  4. Retrieval: A future question is embedded and matched against the memory vector.
  5. Injection: The selected bullet is recorded in platform_memory_injections.
  6. Outcome: Successful execution increments helpful counters; a harmful rule can later be superseded.
  7. Audit: Run and session results are available in synthesis run/detail and job-run tables.
